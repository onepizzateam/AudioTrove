-- DEVELOPER PLAY-BY-PLAY: How to test, debug, and take over Phase 0 --

Overview of what was implemented (Phase 0 core)
- `audiotrove/document.py`: `AudioDocument` dataclass (audio, sample_rate, source_path, duration_seconds, doc_id, metadata).
- `audiotrove/base.py`: `AudioFilter` and `AudioTransformer` abstract base classes.
- `audiotrove/executor/local.py`: sequential `LocalExecutor` with SQLite checkpointing (resumable run).
- `audiotrove/io/readers.py`: `LocalAudioReader` (fsspec + torchaudio; resample/downmix; returns `AudioDocument`).
- `audiotrove/io/writers.py`: `JSONLWriter` (append JSONL manifest entries).
- `audiotrove/filters/vad.py`: `SileroVADFilter` (lazy-load Silero via `torch.hub`, energy fallback if unavailable).
- `audiotrove/filters/snr.py`: `SNRFilter` (VAD-based SNR estimation + energy fallback).
- `audiotrove/cli/main.py`: CLI skeleton (`curate`, `inspect`) using `click` + `rich`.
- Tests updated under `tests/` to match the new `AudioDocument` signature.

If tests fail: step-by-step debug workflow
1) Reproduce failure locally and capture full stack trace (use `-vv`).
2) Identify missing dependency: common failures are `ModuleNotFoundError: pytest` or `torchaudio` or `fsspec`.
	 - Fix: `pip install pytest` or `pip install fsspec` or install `torch/torchaudio` as above.
3) If failing test references audio I/O (reader/writer):
	 - Confirm `torchaudio` can import and `torchaudio.load` works in REPL.
	 - Run a small snippet in Python to load a local WAV and build an `AudioDocument`:
		 ```python
		 import numpy as np
		 import torchaudio
		 from audiotrove.io.readers import LocalAudioReader
		 r = LocalAudioReader('tests/fixtures/*.wav')
		 for doc in r:
				 print(doc.source_path, doc.sample_rate, doc.duration_seconds)
		 ```
4) If VAD tests fail due to missing model download or network issue:
	 - The `SileroVADFilter` lazy-loads via `torch.hub`. Ensure network access or use the energy-fallback path.
	 - To force fallback for debugging, temporarily comment out the `torch.hub.load` call in `audiotrove/filters/vad.py` and run tests.
5) For failing numerical assertions (SNR values, ratios):
	 - Print `doc.metadata` after filter runs to inspect timestamps and computed values.
	 - Example debug snippet:
		 ```python
		 from audiotrove.filters.vad import SileroVADFilter
		 from audiotrove.filters.snr import SNRFilter
		 # construct AudioDocument `doc` as above
		 vad = SileroVADFilter(min_speech_ratio=0.0)
		 vad.filter(doc)
		 print('VAD metadata:', doc.metadata)
		 snr = SNRFilter(min_snr_db=0)
		 snr.filter(doc)
		 print('SNR metadata:', doc.metadata)
		 ```
6) If the executor run behaves unexpectedly:
	 - Verify `doc.doc_id` values are unique and deterministic: run `from audiotrove.utils.hashing import make_doc_id` to inspect.
	 - Inspect the SQLite checkpoint DB: `sqlite3 path/to/checkpoint.db 'SELECT * FROM processed LIMIT 10;'` or use Python's `sqlite3` module.

How to run the CLI locally for quick manual smoke tests

- `curate` currently prints a placeholder; to test end-to-end behavior construct a small script that instantiates `LocalExecutor`, `LocalAudioReader`, pipeline filters, and `JSONLWriter`:
	```python
	from audiotrove.io.readers import LocalAudioReader
	from audiotrove.io.writers import JSONLWriter
	from audiotrove.filters.vad import SileroVADFilter
	from audiotrove.filters.snr import SNRFilter
	from audiotrove.executor.local import LocalExecutor

	reader = LocalAudioReader('tests/fixtures/*.wav')
	writer = JSONLWriter('out/manifest.jsonl')
	pipeline = [SileroVADFilter(min_speech_ratio=0.0), SNRFilter(min_snr_db=0.0)]
	exe = LocalExecutor(pipeline=pipeline, checkpoint_path='out/checkpoint.db')
	stats = exe.run(reader, writer)
	print(stats)
	```
